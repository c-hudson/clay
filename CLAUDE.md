# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**What belongs here and what doesn't.** CLAUDE.md is loaded whole into every session, so it holds only the build commands, the critical rules, the file map and, under "Rules That Bite Everywhere", one to three sentences per rule with a pointer. The detail behind a rule - history, call sites, wire plumbing - lives in `.claude/rules/<area>.md`, path-scoped files Claude Code loads only when a file named in their `paths:` frontmatter is read or edited (never `src/main.rs`, which every session touches); read the file a pointer names when working on that area. A new rule for an existing area goes into its file; a new area gets a new file under 40k chars. Budget: 60k chars and 200 lines, pinned by `claude_md_and_rules_stay_within_budget` in `src/tests.rs`.

## Critical Rules

**All UI changes must be reflected in ALL interfaces.** Any new field, option, or window added to one interface (console TUI, web, webview-GUI, and the native GPUI GUI in `src/native_gui/`) must be added to all of them (the SSH remote console shares the console TUI's renderer, so it usually follows for free). New world/settings fields must also be saved to `~/.clay/settings.dat` in `persistence.rs` and loaded on startup and `/reload`.

**World passwords are stored encrypted in `~/.clay/settings.dat` but sent as plaintext to authenticated WebSocket clients and displayed as readable text in all UI editors.** Do not hide or mask world passwords in the world editor — the encryption is for at-rest storage only. The `has_password` field mirrors whether the password is non-empty.

**Do not write to stdout/stderr once the TUI is initialized (no `println!`, `eprintln!`, `dbg!`).** The rule exists because such output corrupts the ratatui screen (scroll regions, separator bar) after it's been drawn. It does NOT apply before the TUI is initialized, nor in headless contexts that never draw a TUI — startup/config messages before the alternate screen is entered, the `-D` daemon and `--multiuser` server (both headless, including the interactive first-run wizard's operator output), and the panic hook during teardown may use `println!`/`eprintln!` normally. Once the TUI is live, use instead: `debug_log(true, msg)` for always-on logging and `debug_log(is_debug_enabled(), msg)` for user-toggled debug (both write to `~/.clay/debug.log`), `output_debug_log(msg)` for output/seq debugging (`~/.clay/output.debug.log`), and `add_tf_output()` or `add_output()` to display messages in the output area.

## Build Commands

```bash
# Default build command (always use this)
cargo build --target x86_64-unknown-linux-musl --no-default-features --features ssh-transport,shell-worlds
# Output: target/x86_64-unknown-linux-musl/debug/clay

cargo build --features webview-gui   # Build with webview GUI client (ssh-transport included via defaults)
cargo test                           # Run all tests
cargo test test_name                 # Run a single test
cargo clippy                         # Lint
```

**Why musl:** glibc static builds cause SIGFPE crashes during DNS resolution. **TLS is always rustls** (ring): the native-tls backend and the plain-HTTP server went 2026-11-01 - no build used either, and Clay pins certificates itself rather than asking the OS trust store. `rustls-backend` is still accepted as a feature name, doing nothing, so older command lines build.

**`ssh-transport`** (SSH-tunneled `--console`/`--gui`, see `src/ssh.rs`) is in `[features] default` in `Cargo.toml`, so any build WITHOUT `--no-default-features` gets it automatically. Any `--no-default-features` invocation must add it back explicitly or the binary silently loses `--ssh`/`--ssh-proxy` support (`--ssh` exits with "requires the 'ssh-transport' feature" instead of erroring on something more obviously wrong) - this bit us once already; if you add a new `--no-default-features` build command anywhere (a script, this doc, CI), include `,ssh-transport`.

**`shell-worlds`, `multiuser` and `web-front` are compile-time choices** (user rulings 2026-11-07 and 2026-11-09). `shell-worlds` is in `default` too, so every `--no-default-features` line names `ssh-transport,shell-worlds` - except `build-android-aarch64.sh`, the Android app's on-device server, which must never start a subprocess. `multiuser` (the `clay_multi` server: a full Clay per user) and `web-front` (the `clay_web` gateway: a page onto one world) are off by default, in no release asset, never with shell worlds and never together (`compile_error!`): `--no-default-features --features multiuser,ssh-transport` / `web-front,ssh-transport`; `build.sh` builds `./clay`, `./clay_multi` and `./clay_web` (git-ignored; the servers in `target/servers`, so cargo's `target/release/clay` stays the client). A server build started with no interface runs its server (`server::run`). Every client-side part stays in every build (a client must still work with someone else's server). Unused `pub` items don't warn in this crate, so a gate missed shows up only by reading. Test all four sets: `cargo test`, `cargo test --no-default-features --features ssh-transport,native-audio,multiuser`, `cargo test --no-default-features --features ssh-transport,web-front`, `cargo test --no-default-features --features ssh-transport`. → `.claude/rules/build-features.md`, `.claude/rules/instances.md`

### Cross-Platform Builds

- **Termux:** cross-compiled with the Android NDK, no phone needed: `./build-termux-aarch64.sh` / `./build-termux-armv7.sh` (no GUI) and `./build-termux-aarch64-gui.sh` (webview GUI - links against Termux's own packages unpacked by `tools/termux-sysroot.py`, applies the tao/wry X11 patches in a throwaway worktree). No hot reload, TLS proxy, or Ctrl+Z on Android.
- **macOS:** `cargo build --no-default-features --features ssh-transport,shell-worlds` (no musl). Universal binary via `lipo` combining x86_64-apple-darwin and aarch64-apple-darwin targets.
- **Windows:** `set RUSTFLAGS=-C target-feature=+crt-static` then `cargo build --release --features webview-gui` (MSVC, not cross-compiled)

## Architecture

Clay is a terminal-based MUD client built with ratatui/crossterm for TUI and tokio for async networking. Supports multiple simultaneous world connections with SSL/TLS.

### Key Structs

- **App**: Central state - worlds, input area, spell checker, settings, popups, keybindings, TF engine
- **World**: Per-connection state - output buffer, scroll position, connection, unseen lines, pause state, prompt
- **InputArea**: Input buffer with viewport scrolling, command history, cursor position, kill ring
- **PopupManager**: Unified popup system for all modal dialogs
- **WebSocketServer**: Embedded WebSocket server for GUI/web/remote console clients

### Files

**Core:** `src/main.rs` (the application: TUI, event loop, worlds, connections, rendering), `src/apploop.rs` (the one headless setup and loop: `-D`, the GUI masters and every instance), `src/instance.rs` (instances: the thread-local config dir, `Policy`, `Credentials` = password.dat, `KeyIndex`, `InstanceManager`), `src/server.rs` (`clay_multi`/`clay_web`: `server::run`, signals, the cold reload), `src/encoding.rs` (character encoding, colored emoji, console Theme enum, OSC8 URLs), `src/input.rs` (the input area), `src/actions.rs` (triggers: pattern matching, command execution, capture groups), `src/telnet.rs` (telnet negotiation and options), `src/persistence.rs` (`~/.clay/settings.dat`), `src/daemon.rs` (daemon/headless mode, handler B), `src/keybindings.rs` (`~/.clay/keybindings.dat`).

**Networking:** `src/websocket.rs` (WebSocket server, message types, client management), `src/http.rs` (the HTTPS web server; loopback is served plain, a remote plain-HTTP request is redirected), `src/reach.rs` (`ReachabilityInfo`, built by `App::build_reachability_info`, shipped as `GlobalSettingsMsg.reachability_json`), `src/firewall.rs` (Windows Defender Firewall verdict and the elevated Allow rule), `src/portmap.rs` (UPnP IGD port mapping via `igd-next`).

**Chat worlds (Slack/Discord):** `src/chat/` - `mod.rs` (session, `ChatHandle`/`ChatEvent`), `discord.rs`, `slack.rs`, `directory.rs` (name resolution), `spec.rs` (`name`, `#name`, `@user`, id), `render.rs`, `test_support.rs`. User docs `docs/markdown/21-chat-worlds.md`; rules → `.claude/rules/worlds.md`.

**Shell worlds (`WorldType::Shell`):** `src/shell/` - a world that is a local terminal (PTY + `alacritty_terminal`): `mod.rs` (shared types and the three rules), `session.rs` (`shell-worlds` only: the emulator and the `Proxy`), `screen.rs` (`ShellScreen`: ANSI rows, full and delta frames), `keys.rs`, `app.rs`. Clients render it with their line pipeline; wire `WsMessage::ShellScreen`/`ShellInput`/`ShellMouse`. A shell world's output never enters `output_lines`, the log, the archive, TF or triggers. User docs `docs/markdown/23-shell-worlds.md`; rules → `.claude/rules/shell-worlds.md`.

**Map (`/map`, `WorldType`-independent):** `src/map/` - the auto-mapper, built on the server from GMCP room reports: `model.rs` (`MapGraph`, `area_key`), `gmcp.rs` (the area **key** is the game's area id when it sends one, else the name), `layout.rs` (a room is placed once and never moves on its own; a y-axis flip sets `moved_all`), `path.rs`, `walk.rs`, `store.rs` (`~/.clay/maps.db`), `wire.rs`, `text.rs`, `app.rs`; native pane `src/native_gui/ui/map.rs`, app.js "Map pane", console `render_map_pane`. User docs `docs/markdown/25-mapper.md`; rules → `.claude/rules/map.md`.

**Theme:** `src/theme.rs` - ThemeColors (42 color vars), ThemeFile for `~/.clay/theme.dat`; GUI/web only, the console uses encoding.rs's Theme enum. The GUI theme is a **name** (`Settings.gui_theme`, always `theme::normalize_theme_name`d). "Is this a light theme" is `ThemeColors::is_light()` (background luminance), never a name check; app.js `applyThemeAppearance()` is its web twin. The web client's chrome is the native GUI's, in theme-independent CSS. → `.claude/rules/theme.md`

**Popup System:** `src/popup/mod.rs` (PopupManager, field types, layout), `src/popup/console_renderer.rs` (console rendering), `src/popup/definitions/` (individual popups).

**TF (TinyFugue) Engine:** `src/tf/` - `mod.rs` (engine state, variables, macros), `parser.rs` (command parsing/routing, `/help` text), `macros.rs` (triggers, execution), `builtins.rs`, `control_flow.rs`, `expressions.rs`, `variables.rs`, `hooks.rs`, `bridge.rs` (engine ↔ App), `script_tests.rs` (runner for `tests/tf/cases/*.tf`), `effects.rs` (`TfEffect`: what a command did, in order, for the App to apply), `special_vars.rs` (the ones bound to Clay settings), `attrs.rs` (display attributes), `snapshot.rs` (the TF state carried through hot reload), `help.rs` (`tf-help` fallback), `status.rs` (TF's status line); `src/tfrun.rs` (the App side: applying effects, processes, /quote, /sh), `src/tfstartup.rs` (TF command line and `.tfrc`), `src/keynames.rs` (canonical key-name grammar), `src/chords.rs` (chord buffering).

**Other:** `src/kokoro.rs` (the Kokoro neural voice: sherpa-onnx loaded at runtime from the `/tts install` download; → `.claude/rules/tts.md`), `src/selfupdate.rs` (`/update` for every interface; → `.claude/rules/startup-reload.md`), `src/reveal.rs`, `src/picture.rs`, `src/desktop.rs`, `src/crashlog.rs`, `src/info.rs`, `src/scrollback.rs`, `src/newbg.rs`, `src/font_profile.rs` - each has a module doc and a rules file below.

**Web Interface:** `src/web/index.html` (HTML template), `style.css` (uses `var(--theme-*)`), `app.js` (the client), `theme-editor.html`, `keybind-editor.html` (browser-based editors).

**Data Files** (all inside `~/.clay/` on Unix, `~/clay/` on Windows):
- `settings.dat` - main settings (INI, `[global]` and `[world:name]` sections); `secure.key` - per-machine AES-256 key (0600); `theme.dat` - theme colors (`[theme:name]` sections, the four built-ins always present); `keybindings.dat` - non-default bindings only; `multiuser.dat`; `cert.pem` / `key.pem` - the auto-generated TLS cert/key; `media/` - downloaded media; `logs/<WorldName>.<YYYY-MM-DD>.log` - per-world session logs.
- `password.dat` - `clay_multi`'s accounts (`username password`, split at the first space; read at every login, never written; `instance::Credentials`); `users/<name>/` - each user's own Clay directory (settings.dat, secure.key, scrollback.db, maps.db, logs/, ...), where `clay_config_dir()` points on that user's thread.
- `known_hosts.dat` - Trust-on-first-use TLS pins (`host:port` -> hex SHA-256 of the end-entity cert DER) and SSH host keys (`ssh:{host}:{port}`), 0600; `persistence::add_pin`/`replace_pin`/`get_pin`, enforced by `TofuVerifier`. Both halves are lower-cased (`normalize_pin_host`) in every accessor *and* the loader; Android's `CertPinning.java` does the same. → `.claude/rules/security.md`
- `scrollback.db` - SQLite scrollback archive (`src/scrollback.rs`), schema v2 (`PRAGMA user_version = 2`; a pre-v2 file is migrated on first open, `user_version > 2` refused): `worlds`, `output_log(wseq, ...)`, a **contentless** FTS5 index, `archive_meta`. → `.claude/rules/archive.md`
- `maps.db` - SQLite maps (`src/map/store.rs`), `user_version = 1`: `maps`, `rooms`, keyed by `World::world_id` so a rename keeps the map. Its own file: the archive is off by default and a map is wanted without it.
- Logs: `debug.log` (`debug_log()`), `output.debug.log` (`output_debug_log()`), `remote.log` (remote connection events: drops, gate/knock outcomes, bans, WS auth), `dump.log` (`/dump [-w world] [-n lines]`, `App::resolve_dump_scope` for every interface), `settings-audit.log` (debug-mode-only audit of `[global]` changes with the source client and a backtrace).

### Rules That Bite Everywhere

One bullet per rule; the arrow names the `.claude/rules/` file holding its history, call sites and wire plumbing. Design records: `PROTOCOL-ROADMAP.md` (output sync, Phases B-G), `SECURITY-ROADMAP.md`, `TINYFUGUE-COMPAT.md`.

- **Borrow checker with App**: clone data out of App before mutable borrows. **Async lock access**: `try_read()`/`try_write()` on tokio RwLock from sync code, never `blocking_read()`/`blocking_write()` inside the async runtime. **Web content** is embedded via `include_str!()` in http.rs: changes need a rebuild + `/reload`. **TF control flow in macros**: body split by `%;`, blocks grouped by `split_body_preserving_control_flow()`; plain text in loop bodies becomes `SendToMud`, queued in `engine.pending_commands`.
- **WebSocket InitialState**: `build_initial_state()` sends only `output_lines` (NOT `pending_lines`); partial lines are excluded from broadcasts. A client opens on the world it remembers only if that world has connected since the server started (`was_connected`), else the server's current world, else the first that has - one rule in app.js `startWorldIndex` and client.rs `start_world`. **`RequestState` is not a reconnect**: a client's "worlds I asked to resume" record must be consumed by the single `InitialState` after the `AuthRequest`, never held until socket close. → `.claude/rules/output-sync.md`
- **Hot reload**: `exec()` replaces the process, TCP fds survive via cleared FD_CLOEXEC, TLS connections need the proxy process. The HTTPS bind retries only for a successor whose predecessor held the port or a restart, and only while the error is address-in-use; everything else binds once and reports through `http::start_warning`. Listener and accepted sockets are non-inheritable (`platform::not_inherited`). The WebView's duplicate-instance probe detects a reload via the `--reload` arg, never `CLAY_HTTP_LISTENER`. A reload never forces the current world off its splash. → `.claude/rules/startup-reload.md`
- **GUI mode is the default wherever a window can be shown** (user request 2026-10-29; `platform::gui_can_open`); a named interface is never second-guessed. **A restart keeps the interface Clay is in**, and `/reload --console|--gui` switches it only after `App::reload_switch_problem` has checked the successor can run, and only from the main Clay's own window. **A port already taken is not a refusal** (user request 2026-11-01): start-up takes the next free port into `App::web_port_override` (never saved; read the port through `App::web_port()`, never the setting alone); a successor keeps its predecessor's port; `-D`/`--multiuser` keep theirs. **Quitting either GUI runs `/quit`'s cleanup** (`App::quit_cleanup`, bounded 5 s); a reload must never go through that path. **Both GUIs log their window in with the saved web password** (`WsOverride::Saved`), making a per-start session password only without one (never saved). → `.claude/rules/startup-reload.md`
- **Native GUI: `ClayView::after` applies the core's effects itself**, so `self.after(self.session.core.x(), cx)` is complete on its own. **What `ClayView::later` queues runs at the window's next frame, so a close must be queued too**, never decided by `is_open` at call time. **Row counts belong to the styled line they were measured from** (`output::RowCount`), never to a line id alone. → `.claude/rules/native-gui.md`
- **Native GUI: the hamburger is also the desktop's app menu** (user request 2026-10-31, `ui/appmenu.rs`; the WebView GUI has none by ruling): one list (chrome.rs `MAIN_MENU`) on the macOS menu bar and Dock, Linux's GTK `org.gtk.Menus` over zbus, Windows' system menu. **A choice reaches its window by the window's handle, never `update_in`** (GPUI resolves that to the window that last drew the entity). → `.claude/rules/native-gui.md`
- **Both desktop GUIs reach the taskbar through `src/desktop.rs`** (user request 2026-10-31; console, browser and Android excluded by ruling): Taskbar Alert (shown only in the two GUIs' Settings), the ACT badge, `/notify`, and `ensure_desktop_file`, which never rewrites a file that isn't Clay's and never from a cargo `target` build. → `.claude/rules/native-gui.md`
- **Native GUI: a `/window` (follower) shares the main window's connection**; its view upkeep is dropped (`session::is_upkeep`) and the main window reports its followers' worlds with `OtherViews`. **A new client→server message must be gated by an `InitialState` flag** (`other_views`, `expand_line`, `resume_session`, ...): a server closes the connection on any message it can't parse (`WS-BAD-MESSAGE`), so an ungated new message keeps a new client disconnected from an older server. → `.claude/rules/native-gui.md`
- **Native GUI more-mode (`ui/more.rs`): scrollback replies are never arrivals, nothing is drawn below a held line, and it counts rows**; every line from a scrollback reply carries `Line::scrollback`; a release spends the window's own held lines before asking the server. **More-mode is per world in both clients, as on the console**: leaving a world counts afresh only when it holds nothing, nothing is held at a connect. → `.claude/rules/native-gui.md`
- **The native GUI's window zoom (`^+`/`^-`/`^0`) is per window and in memory only** (user request 2026-11-10; `src/zoom.rs` `ZoomState`: 1.2× a level, -7..7, a window that would outgrow its monitor becomes the monitor's work area with the window manager's frame taken off - `zoom::Frame`, X11 `_NET_FRAME_EXTENTS` - a clamped level steps no further, a user's resize re-bases, 1:1 restores the original bounds): the text is drawn at `ClayView::text_size()` (= `font_size` × zoom) and nothing writes `font_size`, so the slider and `apply_settings` keep the saved size; GPUI has no move API, so `ui/zoom.rs` moves the window itself per platform. **Native GUI only by ruling**: app.js returns false for the three ids and leaves a browser's own zoom alone (`ZOOM_ACTIONS`); never a default key with `=` in it (keybindings.dat and `/bind` split at `=`). → `.claude/rules/native-gui.md`
- **The output's scroll bar is drawn the same everywhere on a desktop** (native `ui/output.rs`, style.css `body.device-desktop`): an 8px thumb, no track, its strip reserved even when nothing scrolls. In the browsers `scrollbar-width`/`scrollbar-color` stay unset under `@supports selector(::-webkit-scrollbar)`; natively a thumb drag *replaces* `Scroll::pending`. → `.claude/rules/native-gui.md`
- **`/note` is one function for every console** (`App::run_note_command`), and **`/note <file>` is a file on the main instance's machine from every interface** (user ruling 2026-10-16; `FileEditorState`/`SaveFile`/`FileSaved`). The editor's keys are `input_handler::handle_editor_key`, asked before popups; `UpdateNote`/`McpEditSet` are by index, so `fixup_indices_after_remove` moves the editor's world too. → `.claude/rules/interfaces.md`
- **`/help` has one first page and one text per topic**: the console's first page is `help::HELP_LINES` and TF's bare `cmd_help` returns it; a topic is looked up in help.rs's `get_topic_help` first in every interface (a test fails when a `cmd_help` arm shadows one). The browser editors are `/help web`'s (user ruling 2026-11-04). → `.claude/rules/interfaces.md`
- **Each interface's Settings shows only what acts there** (user ruling 2026-10-26), and a hidden setting is only hidden: its value is still sent back by Save. A new setting goes only where it has an effect; settings that act on the server stay everywhere. **One exception by ruling (2026-10-27): Separator Style** is global and shown in every Settings window, applied through `App::set_separator_style`; the console's own Setup save broadcasts `GlobalSettingsUpdated` as a client's does. → `.claude/rules/interfaces.md`
- **Every interface does what the main instance does** unless the user ruled it interface-specific (ask before leaving one out). **There are two server handlers**: only the console TUI master uses handler A (`App::handle_ws_client_msg` / `handle_ws_send_command_impl`); `--local-server`, the WebView GUI master, the native GUI's in-process Clay and `-D` use handler B (`daemon::handle_daemon_ws_message`) - a client-facing behaviour goes in one shared `App` method both call, never into one handler's arm. **A client's typed line is routed as the console's is** (`App::client_line_for_tf` at both handlers' outer entry, never the internal re-dispatch), and what it leaves for an input line, title or filter goes back to that client (`send_client_tf_ops`). → `.claude/rules/interfaces.md`
- **The SSH/remote console reconnects** (`run_console_client` → `reconnect_once`) after `ServerReloading` or any drop, keeping the TUI, input and editor and logging in again with the kept password **hash**; a refused login or a changed certificate stops the retries; a certificate is never trusted without the first connect's y/N prompt. → `.claude/rules/console.md`
- **Import Picture uploads on the server, for every interface** (`src/picture.rs`): the main console in-process, every other interface in acknowledged chunks, gated by `InitialState.picture_upload`; a batch inserts its links by **one rule** (`picture::link_insertion` and its three ports). **A terminal drop is a path**, asked about before uploading (user ruling); `DropSniffer` uses `crossterm::event::poll(Duration::ZERO)`, never `EventStream::now_or_never()`. → `.claude/rules/import-picture.md`
- **A world leaves `App::worlds` only with `fixup_indices_after_remove` and a `WorldRemoved` broadcast**: the fix-up moves everything the server keeps by world index the way every client moves its own list. → `.claude/rules/worlds.md`
- **The Activity world is a real `World` with `is_activity` set** (user request 2026-11-05; last in the list, none in multiuser, skipped by settings.dat and every world list, reached only by name). `copy_to_activity` gives **each interface its own copy**: only while it shows the Activity world, never a line from a world it shows itself, and a world coming on screen drops its lines from that copy. The console's copy is the world's own `output_lines`, born viewed and **never broadcast** - the one exception to "every line in `output_lines` is broadcast"; a client gets its lines as unnumbered `ServerData` (seq 0). Each copy starts empty: `note_activity_viewers` flushes at every client message, every console draw and before each copy - a new place that moves a view without one of those leaves stale lines. → `.claude/rules/worlds.md`
- **Esc-w's fallback world is per viewer, and kept by name** (`App::calculate_oldest_pending_world_from(current, history)`, TinyFugue's `world-q.tf` rule); a client's history is computed by `App::client_history_after` at every site that moves its view - miss one and that client's Esc-w stops at "no activity". → `.claude/rules/worlds.md`
- **`/window --grep`**: a half-height WebView with `GREP_MODE` injected; client-side filtering of displayed text (ANSI + MUD tags stripped), no server changes.
- **Console rendering**: `render_output_crossterm()` bypasses ratatui for the output area (raw crossterm for ANSI fidelity); popups use ratatui. **Wherever ANSI text has to become ratatui spans use `rendering::ansi_line(text, base)`, never a crate** (ansi-to-tui dropped multi-parameter SGRs and turned a reset into `Color::Reset`). → `.claude/rules/console.md`
- **The text-reveal effect lives in `src/reveal.rs`, and every interface draws it at paint time only**: a transform keeps every row's visible width, so paging, more-mode and hit-testing never see it. **The setting is per interface** (user ruling 2026-10-25: console `Settings::text_reveal`, the rest under their key in `text_reveal_profiles`). Custom and New Only ask for their number only on Enter or Save, never on a key step through the list (user rulings 2026-10-26). Only the renderer's return value arms the frame timer. → `.claude/rules/text-reveal.md`
- **Output is a grid in the GUIs too**: box drawing, block elements and spaces on a background are exact cells; any other one-column symbol above Latin-1 (`core::style::glyph_fit_candidate`, app.js `EMOJI_TEXT_OR_FIT`, pinned together by a test) is measured and fitted to one cell (tolerance a thousandth, not 2%). `tests/native_gui/corpus.ans` "FANSI symbols" is the check. → `.claude/rules/native-gui.md`
- **A world's Login Command runs where a login finishes, and only there** (`App::run_login_commands`, called at the three places Clay's auto-login completes); a new login path must call it; never run without Clay's own login. → `.claude/rules/worlds.md`
- **A keepalive's reply is gagged by one check, `World::is_keepalive_reply`** (the `##rand##` marker or a Custom keepalive's Gag Text, within `telnet::KEEP_ALIVE_GAG_WINDOW`); every world editor shows `telnet::KEEP_ALIVE_RAND_WARNING` while a Custom command lacks `##rand##`. **A client never drops the reply**: it is a gagged line shown under F2. → `.claude/rules/worlds.md`
- **Only a guess comes from timing, and a guess never takes text out of the output** (user rulings 2026-11-03): prompts come from GA/EOR (`PromptSource::Marker`) or `promote_due_timed_prompts`; `WONT ECHO` marks nothing. ### Connection Security

Incoming connections are gated in `src/http.rs` before anything is served. Design record `SECURITY-ROADMAP.md` (D1-D8), user-facing `SECURITY-NOTES.md`, full rules → `.claude/rules/security.md`.

- **Stealth path** (`web_path`, default `clay`): any other path from a non-localhost client is silently dropped and strikes (favicons excepted); localhost always works at `/` and `/clay/`. Routing is the pure `decide_route()`; `SecurityGate` carries the shared state into every server variant.
- **Accept-time IP gate**: with a non-empty allow list, non-listed non-localhost IPs are dropped before the TLS peek (`GATE-DROP`, deliberately not a strike). Allow-list membership never skips authentication.
- **CLAY-KNOCK v1**: an in-band auth-key preamble before TLS/HTTP (first byte `0xC7`); a knocked connection may WebSocket-upgrade at any path but never fetch a page, and still performs normal WS auth. The key is `SecurityGate.auth_key: KeySource` - the one Clay's, or every `clay_multi` user's (`instance::KeyIndex`, each compared in constant time). **WS auth matrix**: no allow list → password or auth key from anywhere; allow list set → password only from listed/localhost/whitelisted addresses, everyone else must knock. **Connection floods strike**: more than `CONN_RATE_MAX` new connections in `CONN_RATE_WINDOW` from one address (`http::ConnRateLimiter`, every server variant; loopback exempt).
- **Ban exemption (D6)**: `SecurityGate::strike()` is the one chokepoint every probe-strike site calls; it never bans localhost, a runtime-whitelisted IP or a *specific* allow-list match (a bare `*` confers nothing). Failed WS password auth still bans (threshold 5). `redirect_http_to_https()` reuses `decide_route()`.
- **Debugging**: `~/.clay/remote.log` (`HTTP-DROP`, `GATE-DROP`, `KNOCK-*`, `WS-PATH-DROP`, `BANNED`, `CONN-FLOOD`, `TLS-*`; the servers' `INSTANCE-START`/`INSTANCE-ATTACH`/`INSTANCE-ENDED`, `WS-INSTANCE-GONE`; output-sync `SEQ-LEDGER`/`SEQ-HOLE`/`SEQ-AUDIT`, `SCROLL-JUMP`, `WS-BAD-MESSAGE`). A silent drop is intentional. `log_remote_event()` is a no-op under `#[cfg(test)]`.
- **The Clay password never crosses a network in the clear**: `GlobalSettingsMsg.ws_password` is always sent empty and an empty `UpdateGlobalSettings.ws_password` means *unchanged* (clearing is console-only); a bare hash or raw auth key is accepted only from loopback (`websocket::plain_credential_allowed`); plaintext `ws://` only to a loopback host (`util::is_loopback_host`); a spawned GUI window inherits the login in-process only, never via a URL.
- **Outbound TLS is pinned, not CA-verified (D7)**: every client-side connection uses `platform::danger_rustls::TofuVerifier` (a mismatch blocks and offers "trust new cert" in every UI). **The signature-verification methods MUST do real verification.** Secret files go through `util::write_secret_file`/`secure_create_file`/`secure_append_file`; static-secret comparisons use `util::constant_time_eq`; multiuser handlers check `world.owner == username`; MUD text reaching the web client is escaped.
- **The web server is always TLS-capable for remote clients; localhost is always plain (D8)**: `web_secure` is kept for compat and never read; `resolve_web_cert_files()` picks a user cert or the auto-generated one in `Settings.web_cert_pem`/`web_key_pem`; the accept loop serves a loopback connection plain and redirects a remote plain request; `-D`/`--multiuser` use the same server. **The one exception, by user ruling 2026-11-11: clay_web with no `cert_file` in web.dat serves plain HTTP to everyone** (`start_https_server(tls: None)`: no acceptor, a remote plain request is served, a ClientHello is `TLS-ON-PLAIN`; app.js `buildCandidates` allows `ws://` to a remote host only on such a page). Auth Key is read-only in Settings; Copy/Regen/Delete live in Modify Key.

### TinyFugue Compatibility

Clay's TinyFugue (TF) compatibility layer (`src/tf/`) and its keybinding grammar (`src/keynames.rs`, `src/chords.rs`, `src/keybindings.rs`) are specced against real TF 5.0 in `TINYFUGUE-COMPAT.md` (design record) and `docs/markdown/06-tf-commands.md` / `07-keyboard-shortcuts.md` (user-facing); full rules → `.claude/rules/tinyfugue.md`.

- **Script-test suite**: `tests/tf/cases/*.tf` + `.expected`, run via `cargo test tf_script`; generate an `.expected` with `tools/tf-oracle.sh --write <name>.tf` from real `tf` (`apt install tf5`), never by hand. **The xfail ledger** (`tests/tf/xfail.txt`): a known-failing case is listed, not left red; a listed case that starts passing fails the suite. Never add an entry without a real, understood gap behind it.
- **Key-name grammar and dispatch order**: every key name is canonicalized through `keynames::parse_key_name`/`KeySeq::canonical`; a pressed key resolves (1) a `/bind`/`/def -b` match, (2) a `key_<name>` macro, (3) the built-in action table, (4) literal input - identically on console and clients.
- **Four-site rule for a new action id**: `ACTIONS` in keybindings.rs plus `dispatch_action` (console), `dispatchActionImpl` (app.js), `dispatch_remote_action` (`src/remote_client.rs`, its own copy) and the keybind editor's action list (a new category also needs adding to its `order` array). `RunKeyBinding{key, kbnum}` is how a remote client runs a TF `/bind` the server told it about.
- **The engine records, the App applies**: a TF command's doings are ordered `TfEffect`s (`src/tf/effects.rs`) applied through `src/tfrun.rs` (`apply_tf_effects_now` + `deferred_tf` for hooks and triggers); never act on a `tf_engine.execute` result itself. A special variable bound to a Clay setting emits `TfEffect::Setting(name, value)` with the value in the effect. Clay has no non-visual mode (user ruling): `%visual` always reads `on`.
- **TinyFugue startup** (`src/tfstartup.rs`): TF's command line and the first `.tfrc` run once at a cold start, never on a reload or crash restart (the TF snapshot carries the state). `-v` stays "version"; nothing auto-connects (user rulings). **Tests never touch the real `~/.clay`**: under `cfg(test)` `get_home_dir()` is a per-process temp home; a test needing a port takes `testserver::free_port()`, never "bind port 0, read it, drop it, bind again".
- **TF's status line** (`src/tf/status.rs`) replaces Clay's separator bar only once a script changes it (`StatusLayout::customized`); keep the Rust and JS layouts identical. **Separator Style is the look of TF's line too** (user ruling 2026-10-28), applied through `App::set_separator_style`, which on TinyFugue → Web calls `status::reset_to_clay`.
- **Two traps**: `%;` is **not** quote-aware (real TF splits on every `%;`), and TF does **not** expand `%var`/`$[...]`/`$(...)` on a bare top-level line read from a file - only in a macro body or via `/eval`.
