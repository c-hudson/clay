# Fixed (Job 15b-i, 2026-09-03): derived TF's actual escaping rule by
# direct experiment against real tf (`/eval /echo [%{x}] [%%{x}]
# [%%%{x}] [%%%%{x}]` -> "[5] [%{x}] [%%{x}] [%%%{x}]", same for a bare
# run of "$" before "[...]") - a run of N consecutive '%' (or '$') is a
# live substitution introducer ONLY when N == 1; N >= 2 collapses to
# EXACTLY (N - 1) literal characters, with whatever follows left
# completely untouched this pass. Clay's old code instead did a naive
# pairwise "%%" -> "%" collapse and then evaluated the leftover single %
# immediately, which is why an odd-length run (color.tf's own
# "%%%{red}") evaluated one nesting level too early. Rewrote the run-
# length handling in variables::substitute_variables (%) and
# variables::substitute_commands ($), and matched control_flow::
# split_percent_semi's own "%;" run-length check to the same rule (a
# "%%%;" 3-run must NOT split until it's been reduced to a bare 1-run by
# two prior substitution passes - needed for the SAME triple-nested /for
# to place its literal "%;" separator between two /set commands at the
# right depth too). The other half of the fix: real tf substitutes a
# nested /for or /while's own header and body text once PER ENCLOSING
# ITERATION (tf-help /for: "<Commands> are executed in a new evaluation
# scope") - control_flow::execute_for_loop/execute_while_loop used to
# skip substitution entirely for any body line that looked like a nested
# /if, /while or /for, deferring completely to the inner construct's own
# single pass, which is one pass short for nesting deeper than one level.
# Fixed by always substituting a nested /while or /for there (still NOT a
# nested /if - verified separately that an /if needs no extra escaping,
# since its own dispatch, execute_inline_if_block, already substitutes
# each branch line itself; doing it twice there corrupts any
# already-resolved value that happens to contain a literal % or $, which
# is exactly what broke crypt.tf's byte-at-a-time cipher construction
# during this fix - see test_encrypt_decrypt_roundtrip/test_load_crypt_tf,
# both green again once the /if exclusion was restored). Deliberately did
# NOT make the analogous change in macros::execute_macro_with_context (a
# MACRO's own body, at CALL time, must keep skipping ALL THREE - a bare
# `/def loopmac = /for i 1 3 /echo n=%i` then `/loopmac` needs "%i" to
# reach /for's own per-iteration pass unresolved, not be pre-emptied to
# "" here before the loop variable exists at all; this is what
# test_for_command_form_nested_in_macro_body pins). lib_color passes
# outright now and was removed.
