# Text-to-speech and Kokoro

Design record for the Kokoro engine and the per-interface TTS profiles. Claude Code loads this file when one of the paths above is read or edited; CLAUDE.md ("Rules That Bite Everywhere") keeps each rule as one sentence with a pointer here. The text below is the full detail, history and function names, moved verbatim from CLAUDE.md on 2026-11-08.

- `src/kokoro.rs` - the Kokoro neural voice (`TtsMode::Kokoro`): the sherpa-onnx C API mirrored as `repr(C)` structs and loaded with `libloading` from the runtime that `/tts install` (or `clay --tts-install`) downloads into `~/.clay/tts` with the model, one worker thread per engine (lazy model load, sentence-by-sentence streaming into rodio, latest-wins), `/tts status|install|remove|voices|voice|test`
- **Kokoro TTS is loaded at runtime, never linked** (`src/kokoro.rs`). `TtsMode::Kokoro` runs Kokoro-82M through the sherpa-onnx C API, which `/tts install` downloads (runtime for this platform + the model build `kokoro::preferred_model` picks for the CPU: int8 `kokoro-int8-multi-lang-v1_0` where 8-bit matmul has a fast path (x86 AVX-512 VNNI, ARM), else the full `kokoro-multi-lang-v1_0` - on AVX2-only x86 the int8 build is ~4x SLOWER (0.95 s vs 0.26 s for a 1 s sentence on a 5600X; slower than real time on an i5-8400T), `install_in` accepts either and `/tts install` replaces the wrong one; the worker reloads a session whose model directory is no longer the install's, and the switch leaves the old build's directory in place until `kokoro::remove_stale_build` at the next start, because sherpa-onnx initialises espeak-ng ONCE per process with the first model's `espeak-ng-data`: delete that directory under a loaded session and every later line is a 0.2 s blip, reload or not) into `~/.clay/tts` (`CLAY_TTS_DIR` overrides) and `libloading` opens on the first utterance - so the binaries stay the size they are, no build machine needs the libraries, and every build has the mode (the static musl console reports that it cannot load a shared library; `/tts install` and `kokoro::build_can_load` say so). The `repr(C)` config structs mirror **one** header version (`kokoro::RUNTIME_VERSION`, pinned by `ffi_struct_sizes_match_the_header`); a newer runtime means re-reading `c-api.h`, never just bumping the constant, and `install_in` refuses a runtime at another version. The engine is one worker thread: the model (~1 s) is loaded **ahead** - `Engine::warm` via `App::warm_kokoro` at every single-user startup, on a settings save that leaves Kokoro selected (`note_kokoro_selected`), after `/tts install` and `/tts voice`; the attached native GUI's `warm_kokoro_if_wanted` does the same for its own copy - on every CPU up to eight (`num_threads`), then `SherpaOnnxOfflineTtsGenerateWithConfig` with `max_num_sentences = 1` so the callback streams each sentence into rodio before the next is synthesized (debug.log: "first audio after"), and "latest wins" like the Local engine (a generation counter the callback checks; `tts::stop`/F9 bump it, a warm-up does not). **Idle, the engine must cost nothing**: the audio stream is opened by the first line (never by a warm-up) and closed after `OUTPUT_LINGER` (30 s) of silence - an open rodio stream wakes forty times a second to hand the sound server silence, which it mixes the whole time ("clay is consistently using 10% of cpu and should be idle") - and a settings save that leaves Kokoro, or `/tts remove`, sends `Job::Release` (`tts::release_kokoro` from `App::note_kokoro_selected`; the attached GUI's `warm_kokoro_if_wanted` does the same for its copy): the model (hundreds of MB, the runtime's threads) and the stream go, the library and the idle worker stay, and the next warm-up starts over. Before this the engine outlived the setting: turning TTS off changed nothing. Until the files are installed, Kokoro mode speaks with the Local engine - **never silently**: `tts::speak` returns true for that fallback, `App::speak_text`/`note_kokoro_missing` say so once (and `note_kokoro_selected` at the moment the setting is chosen), and the native GUI attached to another Clay says its own line (`ClayView::KOKORO_MISSING_HERE`), because the voice plays on *its* machine with *its* files - so there `/tts status|install|remove|test` are handled by the GUI itself (`ClayView::tts_command`), only `voices`/`voice` go to the server, which sets the GUI's own voice under its interface key. The console's voice (`Settings::tts_voice`, `kokoro::VOICES`; every other interface's is in its TTS profile, see the next bullet) rides `GlobalSettingsMsg`/`UpdateGlobalSettings` as a string, empty = unchanged/old peer. `CLAY_TTS_WAV_OUT=<file>` writes the audio instead of playing it (tests, headless boxes). Kokoro's waveforms peak at 0.25-0.4 of full scale where espeak and Piper sit near 0.9 ("turned the volume up and can still barely hear it"), so `Sink::push` lifts every sentence by `OUTPUT_GAIN` (2.5), peak-limited to `PEAK_CEILING` - one gain per sentence, never a clip. **Audio opens through `audio::open_output_stream`, never `OutputStream::try_default` directly**: on Linux it prefers the `pipewire`/`pulse` ALSA device over `default`, because on a PipeWire desktop without `pipewire-alsa` `default` is the sound card itself - Clay then played outside the desktop's mixer, no volume control reached it, and Kokoro was "barely audible" next to espeak (which talks to the server) - and the MUD's sounds and the voice must share the same choice. sherpa-onnx reports with `fprintf(stderr)`, which the console cannot survive: `platform::StderrToLog` sends fd 2 to debug.log for the duration of each library call and of the device probe (unix), and `voice_lexicons` hands it ONE English lexicon per voice (GB for `b*`, US otherwise) plus Chinese - both English lexicons at once made it print "Duplicated word ... Ignore it." for every GB entry onto the screen.
- **Text-to-speech is kept per interface, and the server speaks to each client by its own** (user request 2026-10-28: "each interface can have its own setting that can only be set while in that interface"). The console's own is `Settings::tts_mode`/`tts_speak_mode`/`tts_voice` (`/setup`); every other interface's is a `tts::TtsProfile` in `Settings::tts_profiles` under its interface key (`valid_interface_key`: the font-profile keys, `REMOTE_CONSOLE_REVEAL_KEY`; settings.dat `tts.<key>.mode|speak_mode|voice`), Off until it chose one. A client names its key in `AuthRequest.interface_key` (app.js `fontProfileKey`, native `font_profile::native_key()`, the SSH console's two logins; old servers ignore the field), recorded by `App::set_client_interface` at all four login sites. Wire: `GlobalSettingsMsg.tts_profiles` (`Option`: `None` from a server before the split, when a client edits the shared fields as before - `GlobalSettingsMsg::tts_for`/`set_tts_for`) and `UpdateGlobalSettings.tts_profile` (`None` = unchanged), applied only under the sender's own recorded key; a keyed client's legacy `tts_*` fields are ignored, an unkeyed (older) client still edits and is spoken to by the console's (`App::client_tts`). Routing (`App::speak_arrivals`, replacing the old global speak + `ServerSpeak` broadcast): the console with its own when `console_tui` shows the world (F9 mutes only it), and each ready client showing the world (its view or `ws_client_other_views`, not paused, not disconnected - visible or not, so a pocketed phone keeps talking) whose profile is on, with Limit worked out once (`tts::should_speak` mutates the whitelist). `App::speak_for_client` speaks the GUI master's own window here (`own_gui_client`, the old `ws_say` rule) and sends everyone else `ServerSpeak` to it alone; `/say` (`ws_say`, `say_everywhere`) and `/tts status|voice|test` from a client use the client's own. Kokoro warms for whatever speaks on this machine (`local_kokoro_voice`: the console's when `console_tui`, else the own GUI's profile, warmed when its window logs in). Where Kokoro can't speak its voice is hidden and its choices pruned: app.js `ttsDeviceVoiceOnly` (`!WEBVIEW_MASTER`: browsers, the Android app, an attached WebView) offers Off/Local only (`pruneTtsChoices`, before `initCustomDropdowns` copies the select), and a build that can't load Kokoro (`kokoro::build_can_load`, the static musl console) drops it from `setup::tts_mode_options` and hides the voice field.
