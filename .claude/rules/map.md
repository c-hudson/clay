# The map

Design record for the auto-mapper's files and the rules of the server-side walk and the map pane. Claude Code loads this file when one of the paths above is read or edited; CLAUDE.md ("Rules That Bite Everywhere") keeps each rule as one sentence with a pointer here. The text below is the full detail, history and function names, moved verbatim from CLAUDE.md on 2026-11-08. Complements docs/markdown/25-mapper.md (user docs).

- `src/map/` - the auto-mapper, built on the server from GMCP room reports. `model.rs` (`MapGraph`: rooms, a cell index per (area,x,y,z), `area_key`), `gmcp.rs` (pure `Room.Info`/`room.info`/generic parser; the area **key** is the game's area id when it sends coordinates with one, e.g. `#45`, else the area's name), `layout.rs` (a room is placed once and never moves on its own; the y axis's direction is learned by vote and a flip sets `MapGraph::moved_all`, which every copy - views, store - must act on), `path.rs` (BFS, name tiers), `walk.rs` (pure walk state machine), `store.rs` (`~/.clay/maps.db`, a writer thread, keyed by `World::world_id`; deleted worlds' maps purged after `ORPHAN_KEEP_MS`), `wire.rs`, `text.rs` (the console's text map), `app.rs` (`impl App` glue, `MirroredMap` for attached clients). Native pane `src/native_gui/ui/map.rs`, app.js "Map pane", console `render_map_pane`. User docs: `docs/markdown/25-mapper.md`.
- **The map lives on the server and the server walks** (src/map, user rulings 2026-11-01). A walk sends ONE step per room arrival: the next only after GMCP reports the room the route expected; any other room, `Room.WrongDir`, 10 s without a report (`walk::STEP_TIMEOUT`, a sleep arm in every loop via `next_walk_deadline`), a disconnect or Esc/`/map stop` stops it with a line saying why; the walk survives `/reload` (`map_walk_json`). Every room report is recorded whatever F9 says. Traps: **(1)** `/map`'s pane forms (bare, show/hide, area, level, center) are each interface's own like `/split`: typed ones never leave the client, a server-run one goes back as `ExecuteLocalCommand` only to a client in `ws_client_maps` - which a client joins by sending `MapWatch`, so every client sends one at **every login, empty when its pane is closed** (native core `map_watch`, app.js `lastMapWatch = null`, SSH `map_watch_sent = None`); **(2)** an area is keyed by the game's area id where it has one, so a typed `/map area <name>` is sent as typed, resolved by the server (`MapGraph::area_key` in `map_view_target`) and found again by the client under the key the reply carries (`MirroredMap::area_key`, app.js `mapAreaKey`, fed by `MapArea.area_name`); **(3)** the console's map rows depend only on the pane being open and the terminal size (`console_map_block`), never on map data - a changing row count means a redraw, NAWS and TF's RESIZE; every console pane is offset by `map_rows`; **(4)** a picked room's route is from where you were (`Picked.from`/`mapSelected.from`): it is asked again when you move and dropped when you arrive; **(5)** `DEFAULT_GMCP_PACKAGES` includes `Room 1`, and a connection negotiated without it is sent `Core.Supports.Add ["Room 1"]` once (`map_ask_for_rooms`); **(6)** TF's `map.tf` defines `/map`, so `/@map` always reaches Clay's. `InitialState.map` gates every map message (false in multiuser, which has no map); a `/window` follower has no pane.
