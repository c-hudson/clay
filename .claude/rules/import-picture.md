# Import Picture

Design record for picture uploads from every interface. Claude Code loads this file when one of the paths above is read or edited; CLAUDE.md ("Rules That Bite Everywhere") keeps each rule as one sentence with a pointer here. The text below is the full detail, history and function names, moved verbatim from CLAUDE.md on 2026-11-08.

- **Import Picture uploads on the server, for every interface** (`src/picture.rs`; user docs: 04-interface.md "Importing a Picture"). The Settings' `picture_host` (`PictureService`: catbox/sxcu/x0/tmpfiles (2 days; its link is the file's page - the picture's own link is signed per view and lapses in minutes), each `+short` = through `commands::shorten_url_fallback`, or `off`; `UpdateGlobalSettings.picture_host` is an `Option`, `None` = unchanged) picks the host; the main console uploads in-process (`ConsolePictures`, client 0 only when `console_tui` - in a headless GUI master client 0 is the embedded GUI), every other interface sends the file in chunks: `PictureUpload` (base64 of <= `CHUNK_BYTES`; the server caps a frame at 256 KiB), `PictureUploadAck` per chunk (a client keeps `ACK_WINDOW` unacknowledged - Android's OkHttp socket refuses more than 16 MiB queued - and resends from the last ack after `RESEND_AFTER`, because `ws_send_to_client` drops a message when the client's queue is full), then `PictureUploaded { url | error }`. Gated by `InitialState.picture_upload` = `Policy::pictures` (false for a clay_web visitor, user ruling 2026-11-11, whose `PictureUpload` is refused by `message_refusal` too; true for a clay_multi user and the main Clay). Server state (`IncomingUploads`) is keyed by (client, id) - native `/window`s share a client id - capped per picture and in total, dropped on disconnect and on the keepalive tick (`audit_client_acks`). Upload ids are process-wide (`picture::next_upload_id`) and the acks reach every native window (follow.rs leaves them unclassified); a window acts only on its own. A batch (one drop or pick) inserts its links together by **one rule** (`picture::link_insertion`: a space where a neighbour isn't one, the cursor at the link's start; `InputArea::insert_link`, native `Editor::insert_link`, app.js `insertPictureLinks`), or pastes them into a live shell world. **A terminal drop is a path**, asked about before uploading (user ruling; a pasted path looks the same): a bracketed paste (`handle_paste`, the remote console's `Event::Paste`) or, from xfce4-terminal (`vte_terminal_feed_child`) and Windows' console, *keystrokes* - `DropSniffer` treats characters typed while `crossterm::event::poll(Duration::ZERO)` says more input is already waiting as one burst (never `EventStream::now_or_never()`: it leaves crossterm 0.27's wake thread holding a no-op waker and keys stop waking the loop), skips the draw meanwhile, takes a burst that `parse_dropped_paths` accepts back out of the line, and swallows xfce's separate trailing space. Insert mode only (overwrite couldn't be undone); never in a live shell world (keys go to the PTY). Two traps found on real platforms: GPUI judges "hovered" by the last input's *kind*, and a file dragged in from another program never changes it - after any key press every hitbox is "not hovered" and `on_drop` silently never fires (a drag from a file manager sends no ordinary mouse move), so the native view paints `ui/picture.rs` `drop_after_typing_fix`, which answers the drag's first move with a real one; and Android's WebView can't slice a File backed by the photo picker's `content://` link (`NotReadableError`), so `MainActivity` copies each picked picture into `cache/picked/` and hands the page `file://` links.
