# Shell worlds

Design record for shell worlds (PTY + alacritty_terminal). Claude Code loads this file when one of the paths above is read or edited; CLAUDE.md ("Rules That Bite Everywhere") keeps each rule as one sentence with a pointer here. The text below is the full detail, history and function names, moved verbatim from CLAUDE.md on 2026-11-08. Complements docs/markdown/23-shell-worlds.md (user docs) and the module doc in src/shell/mod.rs.

- `src/shell/` - a world that is a local terminal (PTY + `alacritty_terminal`). `mod.rs` (the shared types: `ShellEvent`, `Size`), `session.rs` (`shell-worlds` only: `ShellSession`, the `Term` + event loop + a wrapper thread for bounded teardown; the `Proxy` that forwards emulator events as `AppEvent::Shell`), `screen.rs` (`ShellScreen`: render the grid to ANSI rows + a plain projection, track dirty rows and a lockstep frame counter, build/apply full & delta frames; activity = a cell gained a non-space char), `keys.rs` (one xterm key encoder + the shared `classify` carve-out), `app.rs` (`App` glue: connect, read the screen, activity, input, per-viewer sizing, frame coalescing, exit). Clients render the screen with their existing line pipeline (console `render_shell_crossterm`, native `shell_output`+`OutputSnapshot.shell_cursor`, web `renderShellScreen`). Wire: `WsMessage::ShellScreen`/`ShellInput`/`ShellMouse`, `WorldStateMsg.shell`. User docs: `docs/markdown/23-shell-worlds.md`. Three rules that bite: the `Proxy`'s `send_event` is called under the `Term` lock onto a bounded channel, so it must `try_send` only and never touch the `Term` (coalesce the wakeup); teardown runs on the wrapper thread (the PTY's `Drop` blocks); `platform::reap_zombie_children` must be `waitpid(0)` (our process group), not `-1`, or the PTY child's exit is stolen and the emulator loop spins. A shell world's output never enters `output_lines`, the log, the archive, TF or triggers. Only a build with the `shell-worlds` feature runs one (see Build Commands); a multiuser build never has it, and its startup still refuses a shell-type world in multiuser.dat. Two more: every way a client connects a world through `daemon::handle_daemon_ws_message` (the `-D` and GUI-master handler: `/worlds <name>` - which is what TF's `/connect` becomes - `/worlds -b`, `ConnectWorld`) goes through `start_non_mud_world` first, because the daemon's own MUD connect dialled a shell world's empty address ("Connecting to :...") while the console's path (commands.rs) knew the type; and a client rejecting a delta asks for the full screen **once** (`ShellScreen::awaiting_full`) - every delta still in flight is stale too, and each used to cost another request and another full frame. After `/reload` re-attaches a shell (`adopt_shell_worlds_after_reload`), the program's repaint - the size nudge, the injected "[Clay reloaded]" note - is not activity: `ShellScreen::ignore_activity_until` holds `gained_printable` down for two seconds, or every reload lit a background shell world's indicator.
