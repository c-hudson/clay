# Instances: the two server builds (clay_multi, clay_web)

Design record for `src/instance.rs`, `src/server.rs` and `src/apploop.rs`, written 2026-11-09 with the user's rulings of that day. CLAUDE.md ("Rules That Bite Everywhere") keeps the one-sentence rules; the detail is here.

- **What they are.** `clay_multi` (feature `multiuser`): every user of `~/.clay/password.dat` gets a full Clay of their own in `~/.clay/users/<name>/` - settings, worlds, actions, TF, archive, maps, notes, theme, keybindings - and may do everything a Clay does except touch the server's files or processes, run anything server-wide (`/reload`, `/update`, `/web`, bans, port mapping, firewall, `/reach`), change their password (password.dat is the operator's, read-only) or make a sound on the server. `clay_web` (feature `web-front`): every page that opens is an anonymous visitor with a Clay of its own built from the operator's settings in memory, one world auto-connected at login, every typed line text for it (no `/` commands, no TF), nothing written, at most `MAX_VISITORS_PER_IP` (5) per address and `DEFAULT_MAX_VISITORS` (200) in all (web.dat has no key for either since 2026-11-11). Both: no shell worlds, no hot reload (SIGUSR1 = cold reload); clay_multi's root settings.dat supplies its web server's fields, clay_web's `web.dat` everything (two bullets below).
- **An instance is a regular Clay on a thread of its own.** `InstanceManager::spawn` makes an OS thread (`clay-user-<name>` / `clay-visitor-<n>`) with a `tokio` `current_thread` runtime, calls `instance::set_current(ctx)` first, then `apploop::prepare_app` + `run_app_loop`, inside `catch_unwind` (a panic ends that instance only: `alive=false`, `INSTANCE-ENDED` in remote.log; a user's is respawned from its files at the next login, a visitor's is gone). Why a thread per instance and not tasks on the shared runtime: the ~64 `tokio::spawn` sites in App code hop worker threads, so a thread-local would not follow them - on a `current_thread` runtime every task of the instance stays on its thread. The `std::thread::spawn`/`spawn_blocking` sites inside App code precompute their paths on the caller's thread (the scrollback and maps writers, media downloads) or touch only root-wide logs; `instance::note_unscoped_access` logs `CTX-MISS` once per thread name if a config path is ever asked for off an instance thread after instances have started.
- **The thread-local is the whole file story.** `clay_config_dir()` consults `instance::config_dir_override()` first (creating the directory 0700); **every accessor reads `INSTANCE` with `try_with`, never `with`**: `debug_log` prefixes each line through `instance::log_prefix()`, so it runs from `Drop`s while a thread's locals are being destroyed (and from the panic hook), where `with` panics - the console's `/quit` aborted with "thread panicked while processing panic" at `thread/local.rs`, the hook's own log line panicking over the panic, from the day the prefix went in until the user's report (2026-11-10; `the_accessors_survive_a_threads_teardown`); `get_settings_path()` honours `--conf` for `Main` only. Everything a Clay derives from `~/.clay` (settings.dat, secure.key, known_hosts.dat, theme.dat, keybindings.dat, scrollback.db, maps.db, logs/, media/, dump.log, settings-audit.log) follows; `debug.log`, `output.debug.log`, `remote.log` and `run/` stay the process's (`clay_root_config_path`), and `debug_log` prefixes an instance's lines with `[user:alice]`/`[visitor:7]` (`instance::log_prefix`). The four caches that were one per process are keyed: `persistence::MACHINE_KEYS` and `KNOWN_HOSTS` by file path, `SETTINGS_FILE_FINGERPRINT` by settings path, `platform::CERT_MISMATCH` by `instance::label()` (the `TofuVerifier` runs on the connect task, which is the instance's thread). A visitor has no directory (`config_dir: None` reads the root - the TLS pins of the world it is shown are the operator's - without a `CTX-MISS`, which is for a thread with no context at all), and its policy forbids every write; the GMCP `Load` pre-cache is gated by `sound_here` too, so a visitor's world fills no `media/`. Many threads now write the one debug.log: `debug_log`/`output_debug_log` format a whole line and `write_all` it once (an O_APPEND write is atomic; `writeln!` on a `File` issued a write per piece and two instances' lines interleaved mid-line, 2026-11-09).
- **`App::policy` is the one switch, read in shared methods.** `instance::Policy` fields: `parse_commands`, `save_files`, `user_paths`, `processes`, `server_wide`, `sound_here`, `change_password`, `web_fields`, `process_globals`, `auth_key`, `settings_export`, `auto_connect_on_login`; `Policy::MAIN` (all true, no auto-connect) is what every regular Clay runs with, so no existing path changes. The check lives in the shared `App` method both handlers call (CLAUDE.md's two-handler rule): `client_reload_refusal`, `start_server_update`, `ws_remote_attach`, `ws_ban_list`/`ws_unban`/`ws_ban_list_response`/`ws_unban_request`, `ws_reach` + the four reachability methods, `update_global_settings` (the web fields under `policy.web_fields`), `apply_debug_setting` (only `Main` writes `DEBUG_ENABLED`), `ws_change_password` (a single Clay refuses too: it has no accounts), `handle_ws_key_request`/`_revoke`, `ws_settings_export`/`ws_import_settings`, `can_trust_certificate`, `tts_command`, `tfrun::start_tf_shell`, `persistence::save_settings_with_source`, and `App::sound_here()` at every local playback site (`ensure_audio`, `handle_gmcp_media`, `handle_msp_trigger`, `play_ansi_music_console`, `speak_text`, `warm_kokoro`; clients still get `AnsiMusic`/`McmpMedia`/`ServerSpeak`). A visitor's typed line: `daemon::handle_daemon_client_message` sends it as text to world 0 when `!parse_commands`, and `Policy::message_refusal` is the allow table for its other messages. An instance's TF engine starts at `RestrictLevel::File`, and `/restrict file` now also closes `fwrite()`, `tfopen()`, `%TFHELP`, the mail check and the process environment (`/setenv` writes TF's own copy) - genuine fixes for every build. Never decide a behaviour by `instance::kind()` at a call site: add a policy field.
- **One loop.** `apploop::prepare_app(SetupOptions)` builds the App (files or the reload state, the connections carried over, the client table, the web server) and `run_app_loop(LoopOptions)` drives it; `run_app_headless` (the GUI masters, `--local-server`), `daemon::run_daemon_server` (`-D`) and the instances are wrappers. Known gains for `-D` from the unification: it loads the reload state (its `/reload` used to exec and start cold), handles GA/EOR prompts, FANSI login timeouts, timed prompts, pending-count broadcasts and `MediaFileReady`, and runs with an auth key alone. `tf_startup` is a step of its own so each wrapper runs it where it did (the GUI masters after their window's InitialState). An instance's loop takes `InstanceCmd::Shutdown { reloading }` from its manager: `ServerReloading` to its clients when the server execs itself, then `quit_cleanup`.
- **The front attaches a login to its Clay.** `http::WsConnectionState.backend` is `Backend::Single { clients, event_tx }` (every single-user mode, as before) or `Backend::Multi { attacher, login: Users | Anonymous }`. `handle_ws_client` is two-phase: before the login a `Multi` connection has a table of its own; the login names the instance (`Credentials::check` per attempt; a key → `KeyIndex::user_for_response`, then that user's Clay validates it with `handle_ws_auth_key_validation` as a single Clay does, answering with `App::auth_identity()`); `Attacher::attach` (run in `spawn_blocking`, it may start the instance) hands over the instance's `clients` and `event_tx`, the connection is inserted there, `WsClientConnected` and then the `AuthRequest` go to the instance exactly as a single Clay gets them, so `handle_ws_auth_initial_state` is unchanged; a failed `event_tx.send` later means the instance ended (`WS-INSTANCE-GONE`, break); `release` on close ends a visitor's instance (bounded join). `Refused::{TooManyFromIp, ServerFull, InstanceFailed, UnknownUser}` is the `AuthResponse.error`, written straight to `ws_sink` before the `break`: a message queued on the client's channel there is never drained (the loop that drains it is the one being left), and the page saw only EOF (found end to end 2026-11-09; `a_refused_attach_is_answered_before_the_connection_closes` pins it). Client ids are the manager's counter, shared by every instance (`WebSocketServer::with_shared_client_ids`). `AuthResponse`/`ServerHello.multiuser_mode` is `MultiLogin::Users`; clients then ask for a username - and try their auth key too (app.js no longer skips the key in multiuser mode; the native core neither).
- **A visitor's Clay is a scrubbed copy.** `InitialState` and `GlobalSettingsMsg` hand an authenticated client the world passwords and the auth key, and a visitor is authenticated with no password, so the template is `Settings::visitor_template()` (web password, auth key, cert PEMs and paths, allow list, debug off) and `WorldSettings::visitor_copy()` (user, password, Login Command cleared; `NoLogin`; no auto-reconnect, no log, no chat tokens); `InitialState.actions` is empty for a visitor (and since 2026-11-11 clay_web has no triggers at all: web.dat can't hold one); `prepare_app` with a template opens no files (`maps_tried`, no archive, no theme/keybinding files). `after_client_login` connects world 0 as that client's connect (`ConnectOrigin::Client { client_id }`, so the First Command's `%host%` is the visitor's address); the page's Reconnect sends `ConnectWorld{0}`. `InitialState.web_front`/`server_sound`/`change_password` tell clients; the page is also told in its HTML (`{{WEB_FRONT}}` → `window.WEB_FRONT`, a string so an unsubstituted copy stays valid), and app.js `WEB_FRONT` hides the menu items but Help/Emoji/Light-Dark Theme/Toggle Tags/Find/Search (CSS `body.web-front`, never the markup - `the_main_menu_is_the_web_menu` pins it to the native menu; Import Picture is in the CSS list but hidden by `picture_upload: false`), the ACT/notes/pause indicators, the phone row's world arrows, tabs and the icon bar; logs in without a password at the ServerHello (`authenticateAnonymously`); sends every typed line as text; blocks the world/reload/quit/expand actions; keeps the text size and its Light/Dark - New choice in `localStorage` (`applyWebFrontTheme`, next-but-one bullet); shows `#reconnect-modal` as the one Reconnect notice on `WorldDisconnected{0}` or a socket close (no retry loop); toggles tags locally (a `/tag` would be text for the game).
- **Spell words are one per process** (`spell::shared_words`, an `Arc<HashSet>` behind a `OnceLock`): the first `App::new` loads the dictionary, every instance's App shares it. A non-Main instance gets `TtsBackend::silent()` (no `which` probe, no Edge task).
- **The servers' lifecycle.** `server::run`: the operator's App on the main thread for the web fields (and clay_web's world) - an App that may have no world at all (clay_multi with no `[world:]`): `add_output` on it logs to debug.log instead of indexing `worlds[0]`, and `resolve_web_cert_files` prints its report there (it panicked at start, 2026-11-09; `output_to_an_app_with_no_world_does_not_panic`) - `resolve_web_cert_files` (clay_multi) or web.dat's `cert_file`/`key_file` checked by `custom_cert_problem` or no TLS at all (clay_web, `start_https_server(tls: None)`), the manager (`seed_key_index` reads each user dir's settings.dat in a scoped context), `start_https_server` on the configured port with `bind_retry = port_released_by_predecessor`, then `wait_for_signals`: TERM/INT/HUP → `shutdown_all(false)` (every instance asked, joined within 5 s) and exit; USR1 → `shutdown_all(true)` then `platform::exec_cold_restart(port)` (the port passed on, the same args minus `--reload`/`--crash`, no fds, no reload state). A user's instance lives until the process ends; a visitor's ends with its socket. Judgment calls (reversible): visitors die with their socket and have no archive/maps/logs; `%host%` is `127.0.0.1` for the console and TF; the rate limit is 30 per 10 s; a user's own `.tfrc` and the operator's are not run for instances (startup actions are).
- **Tests and harness.** `instance::tests` cover the context, the policies, password.dat parsing, `KeyIndex`, a real user instance (start, attach, a login answered with a user's InitialState, shutdown) and visitor caps; `tests.rs` `test_multiuser_login_without_global_password`/`test_security_multiuser_no_user_enumeration` drive `handle_ws_client` against a `MockAttacher`; `daemon::client_parity_tests` cover the policy refusals through handler B; `http::conn_rate_tests` the flood limiter. End to end: `reference/fake-mud-server.py` + `reference/ws-verify-client.py` against `./clay_multi` (a `password.dat` with two users) and `./clay_web` (a one-world settings.dat with `first_command=CLIENT %host%`; the fake server's first line is `CLIENT <ip>`).
- **clay_web's files are `./web.dat` and its neighbours, never `~/.clay`** (user request 2026-11-10: "move all settings to being read from a web.dat file ... in the current directory ... Remove writes to the debug.log ... Nothing actually should write or read to ~/.clay"; rulings the same day: remote.log and an SSL world's TLS pin go beside web.dat as files). The switch is `instance::set_web_only(dir)` (`WEB_ONLY: OnceLock<PathBuf>`, `web_only_dir()`, `is_web_only()`), set by `server::init_web_only` from `main` **before `migrate_legacy_config_files`** - the server decision (`runs_server`: a server build, not attaching, not `-D`/`--console`/`--gui`/`--web-gui`, none of the one-shot modes dispatched between) is computed once there and reused at the dispatch. web.dat is `--conf=`'s file made absolute, else `cwd/web.dat`; its directory is the root. What every disk touch point on the clay_web path does under it (the inventory, from an exhaustive trace): `clay_root_config_dir()` returns the web dir first thing, **without `create_dir_all` or the 0700 chmod** (it is the operator's own directory, often the cwd), so `remote.log` (`log_remote_event`) and `known_hosts.dat` (a visitor's `TofuVerifier` → `check_pin`/`add_pin`; a visitor's `config_dir` is `None` → root) land beside web.dat (no `cert.pem`/`key.pem` since 2026-11-11: clay_web generates no certificate); `debug_log` and `output_debug_log` return at once; `crashlog::record` prints to stderr instead of debug.log (the `session` line not at all since 2026-11-11: the start-up report marks the session; `exit` and `CRASH` still), `session` skips the `run/` directory and marker and calls `imp::log_to_stderr()` so the fatal-signal handler writes to fd 2, `finish` removes no marker; `migrate_legacy_config_files` returns; `persistence::save_settings_to_path_with_source` returns `Ok(())` (web.dat is never written - the operator App has `Policy::MAIN`, so the policy gate alone would not stop it); `load_or_generate_key` never generates (an `ENC:` value reads as empty); `apply_debug_setting` and `load_theme_file` are not called (`InstanceTemplate.theme` carries the operator's `theme_file` to visitors - before 2026-11-10 a visitor's `InitialState.theme_colors_json` came from the built-ins; since 2026-11-11 it is the built-ins by design); `ws_dump` refuses when `!policy.user_paths` (an operator trigger's `/dump` reached `write_debug_dump` past the command gate); `Settings::visitor_template` clears `tls_proxy_enabled` (the proxy's socket path `clay-tls-<pid>-<world>` is the same for every visitor, and a server has no hot reload to need it). `persistence::load_settings` is **not** used for web.dat: it rewrites the file it read whenever `[global]` lacks `url_shorteners` (`read_global_section` → `save_settings`), and `resolve_web_cert_files` (persist=true) would write the generated PEM back too - both were silent writes to the operator's settings.dat before this; since 2026-11-11 web.dat is not settings.dat's grammar at all (next bullet). **The crash log's debug.log is opened at the crash, in every mode**: `imp::install` used to `open(O_CREAT)` it first thing in `main`, so even `clay --version` created `~/.clay/debug.log`; now it prepares the path (`root_config_dir_path()`, a pure path, no mkdir) as a `CString` (Windows: UTF-16) and the handler `open`s, writes and closes (all async-signal-safe); with no directory the open fails and nothing is written, as when the open at start failed. **The settings parser** (`load_settings_from_str_reporting`, which `load_settings_from_str` wraps) skips `#` lines (no key or header starts with one; theme.dat's and keybindings.dat's readers already did), skips a `[theme:` section's keys (`in_theme`, ended by any known header; `ThemeFile::parse` in turn ends a theme section at any non-theme header, so `[world:]` keys are never offered as colours), and returns the unknown keys as `[section] key`; kept for settings.dat (`a_written_settings_dat_has_no_unknown_keys` keeps the writer and the parser in step - `tf_globals_version`, read by the pre-scan, needed an arm) though web.dat no longer uses it. **The sample** is `src/web.dat.sample` (`webdat::SAMPLE`, `include_str!`), written where no web.dat is found, then `exit_process(1, "no web.dat")` (its world is a placeholder). Judgment calls (reversible): web-only is the server mode only - `./clay_web --console=host` is an ordinary attached client with `~/.clay`; crash records on stderr; the sample ends the start rather than running with a placeholder host. End-to-end check: run `./clay_web` with `HOME` set to an empty directory and a fake MUD, and assert no `$HOME/.clay` appears (an `strace -f -e trace=%file` filtered for `.clay` shows nothing).
- **web.dat is a small, strict grammar of its own, and clay_web has no self-signed certificate** (user request 2026-11-11: "change it so that the https interface is only usable when a certificate is provided. Pare down the web.dat ... 5-10 options ... if it's not listed in the sample config, the user shouldn't be able to specify it"; rulings: no certificate = plain http open to all - not loopback-only, not a refusal; the fonts/look group and `web_path` (fixed `clay`) go, the telnet/keepalive group and `world_name` stay). `src/webdat.rs`: `WebDat::parse(text, dir)` reads flat `key=value` lines and `#` comments - exactly `webdat::KEYS` (18: `http_port`, `cert_file`, `key_file`, `world_name`, `hostname`, `port`, `ssl`, `encoding`, `first_command`, `world_type`, `prompt_wait_ms`, the four `keep_alive_*`, `msp`/`mcp`/`mccp2_enabled`); `keys_match_the_sample` pins the list to `src/web.dat.sample` (`webdat::SAMPLE`) in order. An unknown key, a `[section]`, a duplicate, a bad value, `cert_file` without `key_file`, or a missing `hostname`/`port` is `Err("web.dat line N: ...")`, and `load_web_dat` ends clay_web with it (`exit_process(1, "bad web.dat")`); values are trimmed, booleans and names case-insensitive, `first_command` through `unescape_string`, a relative cert path joined to web.dat's directory. `WebDat::apply` builds the operator App from `Settings::default()` + web.dat + the fixed choices (`gui_theme = dark-new`, `status_panel = false`, `picture_host = OFF`, `web_path = clay`, `ThemeFile::with_defaults()`, no actions, one `World` with `status_panel = false`), and `web_front_settings_are_pinned` asserts the whole list the user gave (more-mode on, wrapspace 0, spell check on - `spell::is_valid` is already silent without a dictionary - ANSI music on - the browser plays it, `sound_here` keeps the server quiet - temperature conversion off, input heights 3, clear-on-send off, text reveal Off, `new_indicator` None, allow list empty, 200 visitors), so a changed Clay default shows up there. **Two new `Policy` flags**, false only for a visitor: `pictures` (`InitialState.picture_upload`; `PictureUpload` refused; app.js already hides the item and the drop on `picture_upload: false`) and `gmcp` (`TelnetConfig::gmcp_enabled` → `support_him` answers `DONT GMCP`; `ToggleWorldGmcp`/`SendGmcp` refused; MSDP untouched). A `Policy` flag and not a `WorldSettings` field, because a world field would have to be in settings.dat and every editor; `TelnetConfig` is built at four sites (apploop's connect, commands.rs's connect, daemon's `connect_daemon_world` and `connect_via_tls_proxy`, which both take `gmcp_enabled` now) and each reads `app.policy.gmcp` or is handed it. **No certificate**: `server::run` builds `tls: Option<(String, String)>` - clay_multi's `resolve_web_cert_files`, clay_web's `custom_cert_problem(cert_file, key_file)` (an error at start, never a fallback) or `None` - and `http::start_https_server(server, tls, ..)` takes `Option<(&str, &str)>`: with `None` no acceptor is built, a non-TLS first byte is served plain for everyone (not only loopback), a ClientHello goes to `route_connection` (`TLS-ON-PLAIN`), and the start-up report says `http/<port>`. **That report is the user's three-line format (2026-11-11)**, printed only after the bind: `Clay Portal: <world_name> (<hostname>:<port>) on http|https/<http_port>`, `   Loading settings: <web.dat, relative to the cwd when under it - server::web_dat_display>`, then `   Certificate: <cert_file>` or, with no certificate, `   https disabled - No certificate` **only when the game itself speaks TLS (`ssl=true`)** - the user's "no need to point out there is not a certificate if ssl is set to false", read as the game key web.dat has (a game reached in the clear has nothing to point out); clay_multi keeps its `clay_multi: https://0.0.0.0:...` lines. `build.sh` installs each binary by copy-and-rename (`install_binary`): `cp` over a running `./clay_web` failed with "Text file busy"; app.js `buildCandidates` lets a `WEB_FRONT` page loaded over `http:` use `ws://` to its remote host (the one exception to "plain ws only to loopback": a visitor sends no password and the page itself came in the clear). **The Light/Dark toggle** is the page's own: `ThemeColors::web_front_themes_json()` (`{"dark": dark_new, "light": light_new}`, `null` off the web-front build) fills `{{WEB_FRONT_THEMES}}` in index.html (a string, like `WEB_FRONT`); app.js `applyWebFrontTheme` applies a palette with `applyThemeColors`, keeps the choice in `localStorage` (`clay_web_front_theme`) and relabels the `menu-web-theme` item (`data-action="web-theme"`, in style.css's `body.web-front` list, hidden off the web front); the InitialState and GlobalSettingsUpdated theme blocks are skipped under `WEB_FRONT`, or any settings broadcast (`refresh_tf_bound_keys_if_changed` sends one) would reset the choice; a light-theme visitor sees one dark frame at load (the page is pre-painted with the operator's `dark-new`). Judgment calls (reversible): 200 stays the internal cap (`DEFAULT_MAX_VISITORS`), not "no cap"; unknown keys are fatal, not warnings; `world_name` defaults to the hostname; MSDP stays accepted; the sample keeps the telnet keys the user chose to keep (18 keys, nine under "rarely needed"). End-to-end: a non-loopback peer is the machine's LAN address (`curl http://<lan-ip>:port/clay/` gets the page with `WS_PROTOCOL = 'ws'` and both palettes; `visitor.py` over `ws://<lan-ip>` logs in and the fake MUD sees `CLIENT <lan-ip>`); a fake MUD sending `IAC WILL GMCP` gets `IAC DONT GMCP` from a visitor's Clay and `IAC DO GMCP` from a regular `clay`.
