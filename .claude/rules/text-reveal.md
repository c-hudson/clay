# Text reveal effect

Design record for the text-reveal effect in every interface, its per-interface setting, Custom and New Only. Claude Code loads this file when one of the paths above is read or edited; CLAUDE.md ("Rules That Bite Everywhere") keeps each rule as one sentence with a pointer here. The text below is the full detail, history and function names, moved verbatim from CLAUDE.md on 2026-11-08.

- **The text-reveal effect lives in `src/reveal.rs`, and every interface draws it at paint time only** (tfr's `terminal_reveal` look; console only at first by user ruling 2026-10-24, every interface since 2026-10-25). **The setting is per interface** (user ruling 2026-10-25): the console's own is `Settings::text_reveal` (`/setup`, settings.dat `text_reveal`, never set from a client); every other interface's is in `Settings::text_reveal_profiles` under its font-profile key (`font_profile::native_key()`, app.js's `fontProfileKey`) or `REMOTE_CONSOLE_REVEAL_KEY` for an attached console (settings.dat `text_reveal.<key>=`), Off until it chose one; on the wire `GlobalSettingsMsg.text_reveal_profiles` (the map; absent from an older server) and `UpdateGlobalSettings.text_reveal_profile: Option<TextRevealProfile{key,value}>` (`None` = unchanged), the key checked by `valid_text_reveal_key`. The console: `render_output_crossterm`'s `expand_and_wrap` hands each line's wrapped rows to `Reveal::apply` after the wrap and before anything counts or prints them; a transform keeps every row's visible width (a concealed wide char is two spaces, a zero-width one is dropped, a glitch glyph is one cell) and copies the row's escapes through, closing a styled run with a reset plus the row's own SGR codes, so `display_rows`/`RowMetrics`, paging and more-mode never see it. The native GUI changes no text: `ClayView` stamps lines as `MoreMode::arrivals` shows them (`take_arrived`) or lets them through (`take_released`) and worlds as `follow_world` switches to them (`reveal_at`/`reveal_shown` → `OutputSnapshot.reveal`), `prepare` makes a `reveal::Frame` per laid-out line from the layout's real rows, and `paint` asks `Frame::draw` per character (a hidden one is left out - glyph, background, cell, emoji, underline - a glitch is a glyph shaped on the spot in the accent over the character's place, a fade a colour), so hit-testing and the selection never move; the frame's `next()` goes to `emoji::wake_at`. app.js runs the same algorithm (`revealApply`, a port with the same hash and constants) on the ANSI text just before `parseAnsi`, concealing with SGR 8 (`.ansi-conceal`, `visibility:hidden`) instead of blanks so word-wrap and line heights never change between frames, stamps `lineObj._revealAt` in `appendNewLine` (arrivals and more-mode releases alike) and `world._revealShownAt` on a switch, and redraws the tracked `.line` elements' innerHTML on a 30 fps rAF loop (`revealTick`). A wrapped line's rows reveal together, each behind its own frontier (user ruling: row after row was slow). Speeds are `TextReveal::chars_per_second` (30/60/120/240) everywhere but the native GUI, whose `native_chars_per_second` makes Super Fast 200, and the Android app, where app.js's `textRevealCps` makes it 200 too (user rulings 2026-10-25: 240 was too fast in those two and right in a browser and the WebView GUI). **Custom** (`TextReveal::Custom(cps)`, name `custom:<n>`, `CUSTOM_RANGE` 1..=10000, user request 2026-10-25) is the pickers' last entry: choosing it opens a prompt for the number in every interface - the console's `reveal_speed` popup pushed over `/setup`, app.js `showRevealSpeedDialog`, the native `dialogs::small::RevealSpeed` opened from `SettingsView::text_reveal_changed` - whose OK puts the value on the picker's Custom entry relabelled "Custom (n)" (`setup::set_text_reveal_value`, app.js `showTextRevealChoice`, native `Pick::replace`) and whose Cancel/Esc restores the entry selected before. The console and the native GUI build the list from one `setup::text_reveal_options(current)`; a bare `custom` never reaches a setting (`from_name` makes it Off). **Stepping through the list must never ask, and neither must leaving it** (user rulings 2026-10-26: a console select only cycles, so asking at every step onto Custom put New Only, the entry after it, out of reach; then Down on New Only must move to the next field, "only if I hit return"): the console asks on Enter on either entry (prefilled when it has a number; Enter on a preset still cycles) and on Save while one has no number (`setup::text_reveal_needs_number`; `save_setup` asks first and the prompt's OK finishes that Save, `REVEAL_SPEED_THEN_SAVE`); Cancel leaves the select as it was, a bare entry included (`set_text_reveal_value` keeps a bare `custom`/`new` itself rather than Off). Clicks only cycle. app.js asks at once for a pick from the list, but a closed `<select>` fires `change` at every arrow-key step on a desktop, so a step by key (`revealStepKey`, set on keydown, cleared on keyup) never asks: Enter on the select does, and `saveSettingsAll` does while the select shows an entry `setupTextReveal` isn't (a step onto the entry that shows a number takes that value, `select._revealNumbered`); the prompt hands focus back to the select. The native GUI's select is a dropdown (a pick confirms; no stepping), and so are the phone/tablet pages' custom dropdowns. **New Only** (`TextReveal::NewOnly(cps)`, name `new:<n>`, user request 2026-10-26) is the entry after it and asks for its number the same way (the one reveal_speed popup / dialog, titled by `TextReveal::speed_title`, its entry kept in the popup's `reveal_speed_entry`; `speed_entry`/`with_speed`/`typed_cps` cover both entries): arrivals and more-mode releases reveal as ever, but a world switch types on only lines newer than this interface had shown when it last left the world - the console's `World::console_seen_seq` (`console_reveal_anchor(line, new_only)`), app.js `world._seenSeq` (`revealOptions`), the native `Textdiv::seen` (`reveal_snapshot`), the same marks TF's %textdiv uses, each set at the first draw so a start or reload counts as seen. **What a client holds or catches up on at a start counts as seen until it first switches to that world; after that only live arrivals are new, and a reconnect keeps the marks unless the world's `seq_epoch` changed** (user report 2026-10-26: the first visit to each world typed its whole screen on, "less and less" as each got visited): native `Textdiv` marks are fixed by `arrive`/`leave`, and until then `note_worlds` moves them over `Line::scrollback` lines (the cold start's catch-up after the disk cache), retaking them on a new `World::epoch()`; app.js takes `_seenSeq` after the InitialState hydration (the message's worlds have no `output_lines` yet: taking it before left every mark null), carries a kept `priorWorld`'s mark and `_seenFixed` across a reconnect, and `advanceSeenSeq` moves an unfixed mark in `ScrollbackLines`; the SSH console's `init_from_initial_state` carries `console_seen_seq` by name while the server's `seq_epoch` (now kept on the mirrored world) is unchanged. A switch with nothing new draws the screen whole. ANSI art is cells: a concealed cell is painted with the colours reset (a copied-through background showed the picture anyway) and a space with a background glitches like a glyph, only a bare word gap is left alone (user report: text revealed, FANSI pictures did not). A reveal is anchored by `World::console_reveal_anchor`: `OutputLine::timestamp`, the console's switch to the line's world (`console_shown_at`, set by `App::track_console_world` on a real switch only - never the first draw after a start or a reload - so the screen a switch shows is typed on too, user ruling 2026-10-24) or more-mode's release of the line (`console_released`, seq ranges stamped by `World::note_console_release` in `release_pending`/`release_all_pending`/`selective_flush`/more-mode-off, so a Tab-released page is typed on when it shows, user ruling 2026-10-25), whichever is latest; a line restored by a reload or read from the archive is drawn whole, and a timestamp in the future - another machine's clock in a remote console - is drawn whole too, never hidden. The renderer returns the delay to the next frame only while a line on screen is still revealing, and that return value is the one thing that arms the frame timer (`reveal_sleep` in `run_app`, `reveal_due` in the remote console): nothing fresh on screen, nothing scheduled. A reveal frame is wrapped in DEC 2026 synchronized output; other terminals ignore the private mode.
